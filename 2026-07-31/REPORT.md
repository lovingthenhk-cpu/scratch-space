## Part P: Simons (2008) 本文入手の再挑戦 — 今回は「アクセス権」ではなく「環境側の承認待ち」で止まった

前日は ResearchGate の 429(レート制限)止まりだった。今回はまず
EUDML のメタデータページ (`https://eudml.org/doc/278414`) から、
論文の全文へのリンクそのものを特定できた:

- Full Text (HTML, PLDML): `http://pldml.icm.edu.pl/pldml/element/bwmeta1.element.bwnjournal-article-doi-10_4064-aa131-3-2`
- Full (PDF, IMPAN 出版社直リンク): `https://www.impan.pl/download/pdf/aa131-3-2`
- DOI: `10.4064/aa131-3-2`

**重要な訂正(暫定)**: この DOI (`aa131-3-2`) が正しければ、掲載号は
これまで `PROGRESS.md` に書き続けてきた **Acta Arithmetica 132 ではなく
131** の可能性が高い(`aa131-3-2` は「巻131・号3・その号の2番目の論文」
という命名規則にしか読めない)。MSC分類(`11J86` linear forms in
logarithms、`11B83` special sequences and polynomials)とキーワード
(`generalized Collatz problem, cycle existence, linear forms in
logarithms`)は探している論文の内容と完全に一致するため、論文の同定
そのものは間違っていないはずだが、**巻号(132→131)はまだ2次資料
(EUDML)のみでの確認であり、本文自体では確認できていない**。次回、
本文にアクセスできた際に表紙で確定させること。もし本当に131が正しい
なら、これは「Sultan→Santos」の著者名訂正と同種の「出典を検証せずに
引用し続けていた」ミスの再発なので、次回以降 "Acta Arithmetica 131"
と書くこと(確定するまでは「131(未確定、132の可能性もあり)」と
書くのが正直な扱い)。

**本題(なぜ本文を読めなかったか)**: 上記3つのURL全て、加えて
`https://doi.org/10.4064/aa131-3-2`(DOIリゾルバ経由)、
`https://zbmath.org/1137.11016`(zbMATHのレビューページ)を含め、
**都合5つの異なるURL**に対して WebFetch ツールを呼び出したが、
全て同一のエラーで失敗した:

```
PROVENANCE_REQUIRED: The permission request for this URL was not
answered in time. Ask the user to approve the fetch or include the
URL in a message, then try again.
```

これは前日までの「429」や「空ページ」とは**性質が異なるエラー**である
ことに注意が必要: 429やページが空、というのは「サーバ側/コンテンツ側の
問題」だが、`PROVENANCE_REQUIRED` は**このツール自体が「ユーザーの
承認」を要求している**ことを示すエラーメッセージであり、実際に対話中の
セッション(EUDML の別ドキュメントである `https://eudml.org/doc/205897`
は同じEUDMLドメインなのに一度成功した)では毎回起きるわけではなく、
**特定のURL(おそらく著作権上「認証・課金が必要かもしれない」と自動
判定されたPDF/出版社直リンク)に対してのみ**発生するようだ。

このセッションは**完全自動実行のスケジュールタスク**であり、承認を
求められても応答できるユーザーがその場にいない。したがって、この
特定の障害は「別の検索クエリを試す」「別のミラーを探す」といった
今までの対処法では解決できない。**次回以降への引き継ぎ事項**として
明記する:

- 次に対話セッション(ユーザーが実際に画面を見ている状態)でこの
  タスクが走った場合、または今後同種のタスクをユーザー自身が手動で
  実行する場合は、上記3つのURL(EUDML/PLDML/IMPAN直リンク)への
  WebFetchを試し、承認プロンプトが出たら承認することで本文に到達
  できる可能性が高い。
- 自動実行セッションでは、この種の「出版社直リンクのPDF」は原理的に
  読めない可能性がある。次回の自動実行では、同じURLへの再挑戦に
  時間を使うより、(a) 別の経路(著者の所属大学リポジトリ、
  ResearchGateの別タイミングでのリトライ、Google Scholarの
  キャッシュ版など)を先に1〜2回試し、それでも駄目なら早めに見切りを
  つけて計算タスク(Part Q系)に時間を回すのが合理的。
- **禁止事項の再確認**: このブロックを bash 経由の `curl`/`wget` や
  他言語でのHTTPリクエストで迂回することは、環境の方針で明確に禁止
  されている。今回もそれは一切行っていない(念のため明記)。

この過程で新たに見つけた副産物: 検索中に別の関連論文候補
(arXiv:2008.11103 "On Cycles of Generalized Collatz Sequences"、
arXiv:2201.00406 "There are no Collatz m-Cycles with m≤91"、
ccchallenge.org という Collatz 文献の索引サイト)を確認したが、いずれも
「$q=5$ の $h=4$ 合同類」を名指しでは扱っておらず、Simons–de Weger
(2005, $q=3$ 専用) 止まりの引用に留まっていた。ccchallenge.org は

## Part Q: MITM本番網羅探索の継続 — s=19,21,22 を A=39 まで、s=23,24 を新規に A=38/39 まで

前日 (`2026-07-30/run_production_streaming.py`) は各 A に150秒、各 s に
420秒という時間予算で止めていたが、その停止理由は全て「次のAの推定時間
が予算超過」であって、実際のクラッシュ/OOMではなかった。今回は
バックグラウンド実行なので予算を緩めても問題ないと判断し、
`run_production_streaming_v2.py` で以下の2点を変更した:

1. 時間予算を引き上げ: 1つの $A$ あたり150秒→**400秒**、1つの $s$ の
   累積で420秒→**900秒**。
2. $s=19,20,21,22$ は前日 `production_streaming_results.json` の
   `A_max_reached + 1` から**再開**(ゼロからやり直さない)。
   $s=23,24$ は新規領域として $A=s$ から開始。

実行環境は前日と同じ2コア・8GB RAM(`nproc`/`free -h` で確認)。
`mitm_streaming.py` はそのままコピーして流用(アルゴリズム変更なし、
今回の変更は純粋に「予算の引き上げ」と「範囲の拡張」のみ)。

結果(全て $n_1 \equiv 4 \pmod 5$ の解 **0件**、詳細は
`production_streaming_v2_results.json`):

| $s$ | 開始 $A$ | 到達 $A$ | 検証形状数(brute-force換算, 今回分のみ) | 実時間 |
|---|---|---|---|---|
| 19 | 38(継続) | **39** | $5.125\times10^{10}$ | 327.3s |
| 20 | 39(継続) | 38のまま(前進なし) | 0 | 0.0s |
| 21 | 38(継続) | **39** | $4.948\times10^{10}$ | 320.6s |
| 22 | 38(継続) | **39** | $4.166\times10^{10}$ | 413.7s |
| 23 | 23(新規) | **38** | $1.547\times10^{10}$ | 148.1s |
| 24 | 24(新規) | **39** | $2.514\times10^{10}$ | 315.2s |

今回の合計: $1.830\times10^{11}$(約1830億)形状、実時間
1525.0秒(約25.4分)。**$s=20$ だけは前進できなかった**: 継続開始点
$A=39$ の時点で既に推定コストが予算超過(選ばれた $k=7$ で
streamed側 $3.474\times10^8$ 項、約496秒 > 400秒上限)だったため、
1回もサイクル方程式を解かずに即座に停止した。$s=20$ を伸ばすには
予算をさらに引き上げるか、$k$ の選び方(`choose_k_for_memory_budget`)
を見直す必要がある(次回への課題、下記参照)。

累計(過去日 + 前日 + 今回、$s=9$〜24 の網羅範囲、いずれも0件):

- $s=9$〜18: 2026-07-29までに完了(前日REPORT参照)
- $s=19$〜22: 2026-07-30に新規開拓 + 今回延長(旧 $A\leq37$ → 新
  $s=19,21,22$ は $A\leq39$、$s=20$ は $A\leq38$ のまま)
- $s=23,24$: 今回**完全新規**、$A\leq38,39$ まで網羅

「$n_1\equiv4\pmod5$ サイクルは存在しない」という主張のための下界は
これで $s\leq24$(奇数項の個数)まで、対応する $A$(サイクルの全長、
$s$ ごとに上表の到達値まで)まで拡張されたことになる。証明ではなく
あくまで探索的な下界の拡張である点は変わらない。

### 次回への具体的な引き継ぎ

- $s=20$ が前進しなかった件: 単純に予算をさらに上げる(例: 1

  が選ぶ $k$ が本当に最適か(もっと非対称にすれば streamed 側を
